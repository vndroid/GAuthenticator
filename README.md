# GAuthenticator

二次认证插件 for Typecho

## 插件亮点

感谢原作者 [@WeiCN](https://github.com/naicfeng) ，在此基础上修复 Typecho 新版本的兼容性问题。

相对于旧版，新版的验证逻辑**全部更新**，推荐升级！

- **真正的两步**：密码通过后不会立刻签发 Typecho 登录凭据，先进入一次性挑战，OTP 通过才登录；
- 每个用户使用独立密钥；未绑定 2FA 的用户默认放行，用户可在个人设置中自助绑定和轮换；
- 已绑定用户默认拒绝 XML-RPC 密码认证（pingback 不受影响），管理员可在设置里显式放行；
- 支持可撤销的可信设备、TOTP 防重放和一次性恢复码；
- 待验证挑战保存在每用户服务端状态中，浏览器只持有随机凭据；不依赖 PHP session 扩展；
- 采用插件内注册的 Route 来处理 OTP，无需等待 TP 返回的 2s 后验证；

## 环境要求

- **PHP 8.2.0 或更高版本**
- **openssl 扩展**（用于加密「只显示一次」的恢复码；缺失时插件会拒绝启用）
- Typecho 1.2.0 或更高版本

启用插件时会检查以上条件，不满足会直接给出提示而不是中途报错。

请注意：

- 从 **0.0.1** 升级到 **0.0.2**+ 版本需要**卸载重新安装**！
- 从 **0.1.x / 0.2.x** 升级到 **0.3.0** 后，旧的全站共享密钥不会迁移。所有用户初始视为“未绑定”并默认放行，需分别进入“个人设置”完成绑定。
- 从 **0.1.x** 直接升级时仍需禁用再启用一次，以注册新的登录钩子；从 0.2.x 升级不需要。禁用会删除旧插件配置，所以请先安排重新绑定。
- Typecho 在禁用插件时会删除该插件的全局和个人配置；禁用前请确认所有用户能够重新绑定。

## 设置说明

### 容差倍率

验证码每 30 秒换一个。「容差倍率」决定除了当前这个 30 秒周期之外，前后各还接受几个周期，可选 **1、2、3**，默认且推荐 **1**。

- **1（推荐）**：接受前后各一个周期，实际窗口 90 秒。这已经足够吸收「看到验证码 → 输入 → 提交」这几秒的延迟，以及几十秒以内的时钟误差。
- **2、3（不推荐，仅为特殊场景保留）**：留给长期不校时、确实存在明显时钟漂移的服务器。每调大一档，盲猜命中率会从 `(2d+1)/10⁶` 线性上升，验证码被截获后仍然可用的时间也会按 `(d+1)×30` 秒线性变长。正常情况下应当去校准服务器时间（NTP），而不是调大这个值。

不再提供 **0**。0 表示只接受当前这一个周期，看起来更严格，实际上会造成间歇性的登录失败：用户在周期末尾读到验证码，输入完提交时已经跨到下一个周期，验证就会失败——失败概率约等于「读码到提交的秒数 ÷ 30」；服务器与手机时间相差满 30 秒时更是完全无法登录，连首次绑定都做不了。这类故障时有时无，很难排查，收益（盲猜命中率从 3/10⁶ 降到 1/10⁶）也不足以抵消代价。

**升级提示**：0.3.2 之前该项允许 0–2。升级后，库里所有不在 1–3 范围内的取值（包括 0）都会收敛为推荐值 1。如果你此前特意设为 0，升级后验证窗口会从 30 秒变为 90 秒。

## 丢失验证器

- 优先使用绑定时保存的一次性恢复码登录。成功后系统会提示剩余数量；请进入“个人设置”轮换密钥并保存新恢复码。
- 如果验证器和恢复码同时丢失，只能由有数据库权限的站点管理员删除该 uid 对应、名称为 `_plugin:GAuthenticator` 的 options 记录。该用户会按“未绑定”策略恢复为密码登录，登录后应立即重新绑定。
- 登录时如果提示“两步验证安全配置损坏，已拒绝登录”，说明该用户的安全状态记录已经不是合法内容。出于安全考虑此时一律拒绝登录，也无法从后台自助修复（用户根本进不去），同样需要由管理员删除该记录：

```sql
DELETE FROM typecho_options WHERE name = '_plugin:GAuthenticator' AND user = <uid>;
```

  删除后该用户恢复为“未绑定”，可用密码登录，登录后请立即重新绑定。
- 如果**所有用户**提交验证码都提示“两步验证全局安全配置损坏，已拒绝认证”，损坏的是站点级的 `plugin:GAuthenticator` 配置，不是某个用户的记录。**不需要数据库权限也能自救**：任一管理员用恢复码登录（恢复码不是六位数字，不受这条限制影响），进入“设置 → GAuthenticator”，直接点保存一次即可把全局配置写回正常值。如果所有管理员的恢复码都已用完，才需要由有数据库权限的人重建这一行：

```sql
UPDATE typecho_options SET value = '{"SecretTime":"1","SecretXmlRpc":"0"}'
  WHERE name = 'plugin:GAuthenticator' AND user = 0;
```

兼容所有符合 [**RFC 6238**](https://tools.ietf.org/html/rfc6238 "rfc6238") 规范的 AuthOTP 软件。

- Microsoft Authenticator
- Google Authenticator
- 1Password
- Authy
- KeePass
- LastPass
- ...

## 更新说明

### 0.3.2
- [change] 「容差倍率」改为下拉选择，可选 1、2、3（默认 1），并加入表单校验；不再提供 0，2 以上标注为不推荐、仅为特殊场景保留，该项此前是 `clamp(0, 2)`，把非法输入（例如打错的字）压成 0——也就是只认当前一个时间片，用户输码稍慢或时钟略有偏差就会间歇性失败，严重时无法登录也无法绑定；现在改为白名单，任何非法取值一律收敛为推荐值 1，同时升级后库里不在 1–3 范围内的旧取值（含 0）会在首次请求时就地写正，避免设置页显示的和实际生效的长期不一致

### 0.3.1
- [fix] 修复 MySQL / MariaDB 下保存个人设置必定报「配置正在被并发修改」：条件更新用 affectedRows 做乐观锁，而 MySQL 在写回相同内容时返回 0（SQLite 返回 1），现在内容没变就不再发 UPDATE
- [change] 区分「验证码错误」和「验证码已被使用」：验证器 30 秒内显示同一个数字，刚绑定完或刚登录过再登时手上的码必然已被消费，现在会明确提示等待下一个验证码，并且**不计入失败锁定**（此前连按几次就会把自己锁 10 分钟）

### 0.3.0
- [security] 密钥、开关、最后使用时间片、可信设备和恢复码全部改为按 uid 隔离存储
- [change] 未绑定 2FA 的用户默认放行；旧的全站共享密钥直接废弃，不作为过渡密钥
- [security] 拒绝重复使用已经成功验证过的 TOTP 时间片
- [security] TOTP、恢复码、挑战次数和可信设备的关键读写使用数据库事务与行锁；同时以旧 JSON 值做条件更新，兼容无事务表并避免丢失并发写
- [security] 二次验证失败按 uid 跨挑战累计：10 分钟内失败 5 次锁定 10 分钟，重新提交正确密码不能重置计数，验证成功后清零
- [security] 个人设置的密钥绑定、轮换、恢复码和可信设备变更使用按 uid 行锁事务，避免覆盖并发登录产生的安全状态
- [security] 2FA 放行判定、XML-RPC 策略和挑战读取强制使用 Typecho 的主库连接；读取失败时拒绝认证，不降级放行
- [fix] 旧全局配置的迁移判断改为直接读主库：原先依据 Options 组件（普通读连接）的内容，读写分离下可能拿落后的副本值覆盖主库；同一请求里 `config()` 摘掉旧键后也会读不到
- [fix] TOTP 容差倍率改为从主库读取并按请求缓存，不再取自可能落后的 Options 组件
- [fix] 导航栏状态展示走的是普通读连接，此前仍会在读不到记录时补写默认值；读写分离下副本缺行会因此把主库上真实的密钥、恢复码和可信设备覆盖成默认值（2FA 被静默关闭），现在只有走主库的认证判定才会补建记录
- [change] 最低运行环境提升为 PHP 8.2 + openssl 扩展，并在启用插件时检查；docblock 补上 `@since 1.2.0`，Typecho 版本过低时不再允许启用
- [fix] 激活时预置用户配置的用户列表、存在性判断和补建全部改走主库，避免副本延迟覆盖已有 2FA 状态；全局策略读取错误不再回退到 TOTP 默认容差
- [security] “记住本机”改为服务端登记的随机令牌，可从个人设置注销其他可信设备；服务端只保存令牌散列
- [security] 首次绑定和轮换密钥时生成 8 个一次性恢复码，服务端只保存密码散列，明文仅显示一次
- [security] OTP 挑战改为“随机 HttpOnly Cookie + 每用户服务端状态”，尝试次数、过期和撤销均由服务端控制，并兼容未启用 PHP session 的环境
- [security] 新恢复码通过 AES-256-GCM 加密短期 Cookie 跨重定向展示，服务端不持久化明文，读取后立即删除
- [change] 绑定、轮换、恢复码和可信设备管理迁移到用户“个人设置”；管理员页只保留容差和 XML-RPC 策略
